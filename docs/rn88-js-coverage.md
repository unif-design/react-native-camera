## Behavior changes and equivalent cleanup

1. **Native getter reentry**: a duration getter can synchronously finish, cancel or report failure. `useVideoTransaction.stop` now checks the active operation after sampling before submitting stop. Recorder finish/error/abort paths recheck their pending state after sampling, so a reentrant terminal callback remains the sole result and an undeliverable path is discarded. A clock callback that cancels preparation is checked before native start; the never-started handle is disposed and its produced file returned to the owner.
2. **Timer allocation failure**: the recorder race subscribes to the native signal before allocating its timer. If the scheduler throws, a subsequent native rejection remains observed. The hook cleanup test combines timer, native cancellation and diagnostic failures and verifies the rejection is consumed at the intended lifecycle boundary.
3. **Photo cleanup queue**: the existing version partition, dequeue order, replacement/delete actions and Promise rejection handling were moved verbatim into one internal implementation. The hook uses that implementation; its committed-version state and layout/passive lifecycle remain the scheduling authority. A real-registry test enqueues versions 1/2, consumes only 1, observes version 2 still owned, then releases 2; repeated flush is idempotent. Existing hook lifecycle tests remain intact, including frozen-image release before unlink and unmount cleanup.
4. **Photo processing control flow**: success returns the constructed final file inside `try`; the existing error normalization, raw/partial registration, delegated cleanup and thrown failure remain in `catch`. The former `result == null` fallback was unreachable because every successful path returned raw or assigned final, and every exceptional path produced and threw `failure`. Within the transaction, redundant same-stack currency/mounted checks were removed only between an accepted token gate and pure reducer/metadata operations. Each native/processing/freeze `await` retains its currency check. The same-path postcondition is already enforced in the real processor before native work; the transaction does not accept an injected processor. Accepted `PHOTO_CAPTURED` plus current token implies processing phase, so same-stack `photoSucceeded`/`fail` cannot reject without an invalidated token; real reducer rejection tests remain.
5. **Video cancellation ownership**: private `requestNativeCancel` is called only for the active live operation (start rejection, progress rejection, stop rejection, explicit cancel or layout cleanup). It clears that owner before calling native. The post-getter stop check closes the only discovered reentrant gap. Reentrant cancel therefore sees no active owner; redundant local issued/promise state and null-camera branch were removed. The camera-null startup branch still fails immediately. Native throws/rejections are still consumed in the helper; its callers no longer add unreachable second catches.
6. **Recorder terminal ownership**: Promise resolution is inherently idempotent, so its extra terminal marker flag was redundant. Previously delivered paths are already in `reportedProducedPaths`, and return at the initial dedupe check; a later new path is always discarded. `clearActive` is called only after the still-pending owner is checked (including the new post-sampling checks). A cancelled preparation already clears its pending attempt; after clock cancellation is handled, an accepted preparation owns that slot. Duplicate finish/error, late start, abort reentry and native dispose failures are exercised.
7. **Session settlement**: `SETTLING` accepts at most once; approved recording cancellation additionally owns an epoch through its await. These rules enforce a single notification, replacing a redundant second notified flag. The approved recording request is still current immediately before the pure `SETTLING` transition, so it cannot reject. The remaining cancel phases are exactly configuring/ready/previewing after the earlier transient, terminal and recording cases. External confirmation, settlement-observer and diagnostic failures remain tested.
8. **Factory-bound drain**: `useCamera` always creates its registry locally with `createFileRegistry(RNFS.unlink)`. `delete` catches both unlink and reporter throws; replace/drain await only these fulfilled deletions. The extra drain-rejection log callback was unreachable for this closed factory path and was removed. Separate injectable registry helpers retain their rejection guards and now test real-registry extensions that reject.
9. **Example invariants**: navigation starts with home; push appends a typed route, back never removes the last element, and home creates one route. The empty-stack fallback and runtime never-return case were removed; the explicit ReactElement return type and noImplicitReturns retain compile-time exhaustive checking. A run's only active token is installed by open; reentrant open returns busy and close only aborts, so the success continuation cannot observe a replaced active token before it clears it itself. Observer failure behavior after publication remains tested.
10. **Video preparation**: the private createRecorder callback is invoked only after the real recorder controller rejects a cancelled/disposed attempt. No await/callback occurs before its configuration Promise executor, so that initial aborted check was redundant. The abort listener during configuration and the post-await aborted check remain and are exercised by synchronous configured-then-cancelled ordering and stale output/revision errors.
